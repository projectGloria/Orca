# Orca project review and interface redesign

Reviewed on 21 November 2026 against commit `63091bb` and the interface changes in this working tree. Orca is an Android 14+ downloader. Compose handles input and playback, Room stores transfers, JobScheduler runs downloads, yt-dlp and FFmpeg extract media, and MediaStore publishes the finished files. The app and download engine have independent update paths.

The highest-priority defects are in queue recovery and release retries. A single interrupted or rejected worker can affect unrelated queued items, and a retry can leave a complete release hidden as a draft. The new interface exposes unfinished work in Downloads and preserves the link draft. The redesign also fixes a MediaStore lookup that caused a cancelled save to create a second entry when resumed.

## Project review

The previous [Android app analysis](../artifacts/audit/ANDROID_APP_ANALYSIS.md) describes a pre-fix build. Its [remediation record](../artifacts/audit/FIXES.md) covers the engine backup, publication cancellation, playback lifecycle, activity recreation and ELF audit fixes that are already in the reviewed baseline.

### High priority

| Finding | Evidence and impact | Proposed fix and acceptance check |
| --- | --- | --- |
| A stopped worker interrupts unrelated queued work | `TransferService.onStopJob` cancels one slot but asynchronously runs a global `interruptQueued()`. That update can take work away from the other slot or affect a batch submitted after the callback. The worker cleanup already has access to its own claimed item. [Job stop](../app/src/main/java/io/github/nihil/orca/Downloads.kt#L267), [queue queries](../app/src/main/java/io/github/nihil/orca/Storage.kt#L36), [Android UIDT behavior](https://developer.android.com/develop/background-work/background-tasks/uidt) | Serialize worker ownership and queue changes. Only interrupt a stopped slot's claimed item while another worker can drain the queue. If no worker remains, apply the recovery policy to the affected queue generation. Test a two-slot stop with existing work and a concurrent enqueue. |
| An optional second worker can make a successful enqueue appear to fail | `schedule()` can register the first job, then throw when scheduling the second. Its catch block interrupts every queued row, even if a worker is already registered. Inspection before enqueue also allows the app to lose the visibility required to schedule UIDT work. [Scheduling](../app/src/main/java/io/github/nihil/orca/Downloads.kt#L72), [UIDT scheduling rules](https://developer.android.com/develop/background-work/background-tasks/uidt) | Distinguish zero usable slots from reduced concurrency. Scope the failure state to the affected requests. Keep explicit Resume available when Android rejects all slots and require user confirmation again if inspection finishes while the app is ineligible. Test first-slot success with second-slot rejection and backgrounding during inspection. |
| Release retries can leave a complete draft unpublished | When the draft contains `orca-update.json`, `publish()` returns after comparing version codes. A failed run between manifest upload and `gh release edit` leaves the app unable to discover that draft. A mocked replay reproduced the early return. [Release helper](../scripts/release.py#L58) | When the marker exists on a draft, verify the version and expected assets, then publish the draft. Preserve the read-only behavior for a complete public release. Add tests for both states and an incomplete draft. |

### Medium priority

| Finding | Evidence and impact | Proposed fix and acceptance check |
| --- | --- | --- |
| A crash between MediaStore and Room commits can rewrite a saved file | `publisher.complete(uri)` makes the file public before the Room update records completion. On restart the item becomes Interrupted. Retrying reopens the existing asset, marks it pending, and rewrites it from staging. If staging is gone, a retry can also download the source again. [Transfer finalization](../app/src/main/java/io/github/nihil/orca/Downloads.kt#L179), [publication](../app/src/main/java/io/github/nihil/orca/Storage.kt#L83) | Reconcile persisted publication URIs with the exact expected file metadata and provider state before retrying. Promote an already-complete matching file to Completed without truncating it. Inject process loss before and after each commit and assert there is one intact public file. |
| Resuming a cancelled save created a second MediaStore entry | The emulator regression test observed a different URI on Resume while the original row was still pending. The deterministic filename lookup omitted pending rows. [MediaStore lookup](../app/src/main/java/io/github/nihil/orca/Storage.kt) | The lookup now explicitly includes pending rows. The existing regression test checks that Resume publishes to the same URI. |
| Link parsing can change valid links and accept malformed ones | `LinkParser.fromText` trims punctuation from every match, including exact URL input. A direct filename or signed query can legitimately end with one of those characters. The regex also accepts text with an invalid host and hands it to yt-dlp. Playlist URL acceptance uses a separate prefix check. [Link parser and playlist mapper](../app/src/main/java/io/github/nihil/orca/Engine.kt#L20) | Preserve the bytes of valid direct input, validate HTTP(S) scheme and authority consistently, and apply prose punctuation handling only to extracted candidates. Cover exact URLs, shared prose, IPv6, malformed hosts and signed query strings. |
| Large or slow playlists can block the download flow | The engine reads all JSON output, parses all entries into memory, and starts without a total operation deadline. A socket timeout limits individual I/O waits. The user has no inspection cancel action. A flat playlist entry with a nested playlist can be selected and will later fail the transfer's playlist check. [Inspection and playlist mapping](../app/src/main/java/io/github/nihil/orca/Engine.kt#L80), [transfer inspection](../app/src/main/java/io/github/nihil/orca/Downloads.kt#L143) | Bound output and entry count, add an inspection deadline and cancellation that terminates the native process, and mark nested playlists as a separate supported flow or unavailable. Test slow, empty, oversized, mixed and nested fixtures. |
| Large files can exhaust temporary storage | The original streams, merged staging file and public MediaStore copy can overlap. Failed and interrupted requests retain partial data for Resume. The app has no staging footprint summary or selective cleanup workflow. [Staging and publication path](../app/src/main/java/io/github/nihil/orca/Downloads.kt#L135) | Estimate peak temporary space where sizes are known and expose retained bytes with a purge action for inactive requests. Test exhaustion during download and during publication. Preserve the resumable file when enough space can be freed. |
| Missing files still appear in the saved count | Play and Share check the URI, but a file removed by another app still shows as saved. The redesign moves those checks off the main thread. [Library and playback entry](../app/src/main/java/io/github/nihil/orca/MainActivity.kt), [URI existence check](../app/src/main/java/io/github/nihil/orca/Storage.kt#L55) | Record a missing-file status when access fails, offer removal of the stale entry and a new download with the saved options, and distinguish missing content from temporary permission or provider errors. |
| CI omits the app's highest-value runtime checks | The workflow builds debug APKs and runs lint, JVM and release-helper tests. The existing instrumentation suite exercises JobScheduler, MediaStore, native tooling and the UI on Android separately. [CI workflow](../.github/workflows/ci.yml), [instrumentation suite](../app/src/androidTest/java/io/github/nihil/orca) | Add an x86_64 emulator job for fixture-based tests. Keep the existing release alignment gate and add physical ARM64 and 16 KB runtime runs to the release checklist. |

### Maintainability and release documentation

- Room observes the entire history and republishes it on progress writes. The library filters the resulting list in memory. Use targeted observable queries for active transfers and saved counts, page saved history, and benchmark with a large library and two active jobs. Export the Room schema and add migration coverage before changing persisted fields. [Room storage](../app/src/main/java/io/github/nihil/orca/Storage.kt)
- The quick-download path inspects the source before enqueueing, then the worker inspects it again. Reuse verified metadata when fresh, and decide explicitly when to re-inspect during a retry. Test one normal download, one expired source and one generic playlist URL. [UI inspection](../app/src/main/java/io/github/nihil/orca/MainActivity.kt), [worker inspection](../app/src/main/java/io/github/nihil/orca/Downloads.kt#L143)
- The production manifest enables cleartext traffic app-wide. Decide whether direct HTTP sources are a supported feature. If they are, identify plaintext sources when a link is submitted and keep fixture-only exceptions in the debug manifest where possible. [Production manifest](../app/src/main/AndroidManifest.xml), [debug manifest](../app/src/debug/AndroidManifest.xml)
- The earlier validation records describe older APKs and sample URLs. Keep those results dated and associate future native and live-source claims with the commit, engine version, architecture and Android version used. [Historical validation](../VALIDATION.md)

## UI redesign

| Screen | Implemented changes |
| --- | --- |
| Home | The link field and Download action lead the screen. Paste preserves the existing draft if the clipboard has no usable link. The keyboard can submit the form. Shared links return to Home and populate the draft without starting a transfer. Successful queueing provides a shortcut to Transfers. |
| Downloads | Saved media and Transfers have distinct views. Title search and media-type filters apply to saved files. Transfer rows surface status, progress, cancel, retry and details. A saved row plays on tap, with Share, Original link and Delete in its menu. |
| Options and playlists | The format controls, source preview and entries share one scrolling sheet with a fixed confirmation action. Playlist rows have one accessible checkbox target. Select all represents partial selection. |
| Settings | The bottom bar exposes Settings directly. Download behavior and folders, app and engine updates, and open-source notices each have a dedicated section. |
| Player and chrome | The navy and cyan palette carries through navigation, sheets and dialogs. The player gives the media viewport the available height and keeps the external-player action visible in its regular layout. |

## Verification

- The seven Python release and native-alignment tests passed.
- All 23 JVM tests passed. Both debug APKs and the instrumentation APK assembled.
- Android lint completed with zero errors and 25 warnings.
- The Android 15 x86_64 instrumentation suite passed all 26 enabled tests. The runner listed 29 cases, including three opt-in cases. The MediaStore regression confirmed that Resume reused the pending URI, and the UI suite checked shared-link routing, saved and transfer views, filter reset, playlist selection and playback lifecycle.
- A separate run at 1.5× Android font scale verified that the options sheet kept its confirmation action visible.
- The native audit checked 258 ARM64 and 260 x86_64 ELF files in the debug APKs. All passed the 16 KB segment-alignment check.
- The two-phase force-stop test verified that a persisted transfer becomes Interrupted on relaunch and retains its partial file.
- A local mocked GitHub response reproduced the complete-draft retry defect without contacting or changing a release.
- The runtime checks used a 4 KB Android emulator. Physical ARM64, 16 KB runtime behavior, long network outages and live provider probes remain open. Each code-review finding includes an acceptance check.
